Verify a transcript

Check that a room's JSON download still says what its room's chain recorded. Your browser does the checking: the file is never uploaded & no request leaves this page.

{# Behaviour: static/js/verify.js (chain.verify_message, ported). A file dropped anywhere on this page is checked. #}

A JSON transcript

Drop it here, or pick it. In a room, it is Download history: JSON in that room's controls.

    What is checked

    For each message in the file:

    1. its words hash (SHA-256) to the digest its chain event recorded;
    2. that event's line hashes to the event's own hash;
    3. a Merkle proof leads from that hash to the root named in the file.

    Change one letter of a message, an event line, a proof step or the root, & that message fails, with the check that caught it.

    What is not checked

    • That the root is one our server holds. A file made up whole, root included, agrees with itself. Compare its root with the room's chain (GET /api/rooms/<id>/chain.jsonl, open to whoever may open the room; the file names its path) or with a copy an outside witness kept.
    • That nothing was left out. A message removed from the file, together with its proof, leaves no trace here.
    • Names, roles & tool results. Only each message's words are checked; who the file says wrote them, & what it says a machine learning model's tools returned, are not.
    • Whether the words are true. A verified reply is the reply that was written, right or wrong.
